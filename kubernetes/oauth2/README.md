# Configuring the authentication of the PapyrusWeb application using an SSO (keycloak) and the oauth2 proxy.

This document explains how to configure the PapyrusWeb application to be authenticated using keycloak. It assumes the reader has knowledge about the PapyrusWeb application, as well as core kubernetes concepts.

| :---      |      ---: |

|Req3       | The system shall display the PapyrusWeb main page.|
|ReqQuality1| The system shall use the Kubernetes environment.|

# 2.3 Configuring Keycloak

Keycloak (http://keycloak.org/) will be the SSO (Single Sign On) server used to authenticate the PapyrusWeb application.

Keycloak provides several ways to secure an application, by using application specific adapters. There are Keycloak adapters for Tomcat, Spring Boot, Javascript, nodejs, and others.

The keycloak URL used is https://sso.sample.url

The Papyrus Web URL used is https://papyrusweb.sample.url

## Creating the realm and client entries

It is necessary to create a Realm on keycloak. A realm is a space where the secured objects, such as users, applications and roles are managed. 

* Use an existing realm or create a realm *PapyrusWebApp* . There are several options for configurations. For the sample application, all the default settings are enough.

* create a client *papyrusweb*, with the following properties
  * Client protocol: openid-connect
  * Access Type: confidential
  * Root URL: https://papyrusweb.sample.url
  * Valid redirect URLs: https://papyrusweb.sample.url/oauth2/callback, https://papyrusweb.sample.url*

The credential tab creates a 'Secret', it will be used later.

* Create a mapper with Mapper Type 'Group Membership', with name 'pwebmapper' and Token Claim Name 'groups'.
* Create a mapper with Mapper Type 'Audience', name 'pwebaudience' and Included Client Audience and Included Custom Audience set to the client name (_papyrusweb_).

*Useful link*: https://oauth2-proxy.github.io/oauth2-proxy/docs/configuration/oauth_provider/#keycloak-oidc-auth-provider


# 2.4 Configuring Oauth2

The Oauth2 proxy (https://oauth2-proxy.github.io/oauth2-proxy/) is a reverse proxy that enables authentication of full applications using different providers. We use keycloak as provider and kubernetes as deployment platform.

To install it using helm charts, use command:

```
helm repo add oauth2-proxy https://oauth2-proxy.github.io/manifests

helm install pweboauth2 oauth2-proxy/oauth2-proxy -f values.yaml -n papyrusweb
```
Parameters:
* free name to identify the pod : pweboauth2
* helm chart name: oauth2-proxy/oauth2-proxy
* parameter file: values.yaml
* namespace: papyrusweb

The parameter file has a large choice of parameters (https://oauth2-proxy.github.io/oauth2-proxy/docs/configuration/overview). We used the following values:

```
extraArgs:
  provider: keycloak-oidc
  provider-display-name: "Oauth login"
  client-id: papyrusweb
  client-secret: SECRET GENERATED BY KEYCLOAK
  redirect-url: "https://papyrusweb.sample.url/oauth2/callback"
  oidc-issuer-url: "https://sso.sample.url/realms/PAPYRUSWEB"
  whitelist-domain: ".sample.url"
  cookie-secret: "SOME SECRET"
  # the cookie-expires parameter is not supported in newer helm versions. 
  #cookie-expires: 90m 
```

The extra arguments up to 'oidc-issuer-url' are used to configure the integration with keycloak. The cookie-secret parameter is used to securely store cookies. The cookie expires sets up an expiration time. The default is 7 days (168h). It might not be needed depending on the used helm version.

If the arguments change, the proxy can be updated with the command:

```
helm upgrade pweboauth2 oauth2-proxy/oauth2-proxy -f values.yaml -n papyrusweb
```

Command line to generate a cookie secret:

```
python3 -c 'import os,base64; print(base64.urlsafe_b64encode(os.urandom(32)).decode())'
```

If the generated cookie contains special characters, generate it again. Some special characters may cause interpretation issues.


## 2.5 Creating the Ingress

It is necessary to create two Ingress to use Oauth2 as an authentication proxy. 

* *ingress_oauth.yaml*: an ingress that configures the access to the Oauth2 proxy. 

* *ingress_app_oauth.yaml*: an ingress that configures the access to the Papyrusweb application, using keycloak and oauth2.

Both files are commented, in order to understand specific property values. They can be deployed using the following commands:

```
kubectl apply -f ingress_oauth.yaml -n papyrusweb

kubectl apply -f ingress_app_oauth.yaml -n papyrusweb
```
