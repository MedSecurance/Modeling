= TVRA UML Profile Documentation


This document provides an overview of the `TVRA` UML profile, including stereotypes and enumerations. It has been defined based on the network domain model https://github.com/Spyderisk/domain-network/tree/6a from the Spyderisk Risk Assessment tool https://github.com/Spyderisk.

This profile may be used standalone, when the goal is uniquely to perfom a risk analysis. Otherwise, it used together with the IoMT profile, which defines the core architectural elements.

== Stereotypes

=== TVRAAsset

The `TVRAAsset` stereotype represents an asset within the IoMT, i.e., all the systems' instantiable elements in a TVRA architecture. It annotates any elements of the IoMT architecture.

==== Attributes

|===
| Name | Type | Multiplicity | Description

| kind
| TRVAAssetKind
| 1
| The kind of the TVRA asset. Key property to identify the asset.

| misbehaviours
| Misbehaviour
| 0..*
| The misbehaviours associated with the TVRA asset.

| trustworthinessattributesets
| TrustworthinessAttributeSet
| 0..*
| The trustworthiness attribute sets associated with the TVRA asset.

| controlsets
| ControlSet
| 0..*
| The control sets associated with the TVRA asset.
|===

=== NetworkDomain

The `NetworkDomain` stereotype represents a relationship between two TVRA assets. It annotates existing dependency associations. 
 
==== Attributes

|===
| Name | Type | Multiplicity | Description

| kind
| NetworkDomainKind
| 1
| The kind of the network domain.
|===

=== ControlSet

The `ControlSet` stereotype represents a control set within the TVRA system.

==== Attributes

|===
| Name | Type | Multiplicity | Description

| kind
| ControlSetKind
| 1
| The kind of the control set.

| isProposed
| Boolean
| 1
| Indicates whether the control set is proposed.

| tvraasset
| TVRAAsset
| 1
| The TVRA asset associated with the control set.

| coverageLevel
| TrustworthinessLevelKind
| 1
| The coverage level of the control set.
|===

=== Misbehaviour

The `Misbehaviour` stereotype represents a misbehaviour within the TVRA system.

==== Attributes

|===
| Name | Type | Multiplicity | Description

| kind
| MisbehaviourKind
| 1
| The kind of the misbehaviour.

| tvraasset
| TVRAAsset
| 1
| The TVRA asset associated with the misbehaviour.

| impactLevel
| ImpactLevelKind
| 1
| The impact level of the misbehaviour.
|===

=== TrustworthinessAttributeSet

The `TrustworthinessAttributeSet` stereotype represents a set of trustworthiness attributes within the TVRA system.

==== Attributes

|===
| Name | Type | Multiplicity | Description

| kind
| TWASKind 
| 1
| The kind of the trustworthiness attribute set.

| trustworthinessLevel
| TrustworthinessLevelKind
| 1
| The trustworthiness level of the attribute set.

| tvraasset
| TVRAAsset
|
| The TVRA asset associated with the trustworthiness attribute set.
|===

== Mapping source for defining the assets and related elements

Concerning the mapping between the TVRA concepts (Assets, Misbehaviours, TWAS, etc.), the tools is based in the Domain Network model available here: https://github.com/Spyderisk/domain-network/blob/6a/csv/DomainAsset.csv. We used the URI column, not the Label one, to define the TVRAAssetKind literals.

The table below shows the elements that have different values from the _Label_ and _URI_ columns. The other elements (190+) have the same value for both columns.

[cols="2,2", options="header"]
|===
| TVRA Concept | IoTMT Domain Network Model

| Cellular Access Network
| domain#RAN

| Data Lifecycle Assets
| domain#DataLifecycleAsset

| Data
| domain#DataPalette

| CloudAPI
| domain#APIServer

| IngressProxy
| domain#Ingress

| CloudMaster
| domain#Master

| CloudWorker
| domain#Worker

| IOT Actuator
| domain#Controller

| IOT Sensor
| domain#Sensor

| Users and Governance
| domain#GovernancePalette

| Hosts
| domain#HostPalette

| Networks
| domain#NetworkPalette

| Laptop
| domain#Notebook

| Process Types
| domain#ProcessPalette

| Physical Locations
| domain#PhysicalPalette

| IOT HealthSensor
| domain#HealthSensor

| ClientServiceRelationship
| domain#ClientChannel

| ClientServiceChannel
| domain#ServiceChannel

| ReverseProxy
| domain#ServiceProxy
|===


For the other elements, we used the values below:
